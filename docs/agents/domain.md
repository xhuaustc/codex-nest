# Domain Docs

This repo uses a single context. The glossary lives at `GLOSSARY.md` and architecture decisions live in `docs/adr/`.

Before exploring, read the glossary and any ADRs that cover the area you will work in. If the files don't exist, continue. Use the domain-modeling skill to create them when a term or decision is settled.

Use the terms defined in the glossary in issues, proposals, and tests. If a term is missing, check whether the repo has an established name and note any gap for domain modeling.

If a proposal conflicts with an ADR, name the ADR and explain why the decision should be revisited.
